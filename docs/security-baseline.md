# ForkStream security baseline — Part 02

This is a deliberately limited first enforcement layer, not a production-security certification.

## Controls implemented

- All `/api/*` routes require the owner bearer token or a signed, expiring browser cookie, except the auth status/unlock endpoints. The owner token is randomly generated if not configured, stored outside the API in `data/owner-token` with restrictive file permissions where supported, and ignored by Git. To display it locally, run `npm run auth:token`.
- The API and Vite dev server bind to loopback by default for the intended single-owner local test setup. `FORKSTREAM_HOST=0.0.0.0` is an explicit override only for a trusted external preview proxy; it is not a public-deployment profile.
- Browser sessions use `HttpOnly`, `SameSite=Strict`, `Path=/`, a 12-hour expiry, and no `Domain`. HTTPS responses use the `__Host-` cookie prefix and `Secure`; HTTP localhost development uses a non-prefixed cookie because `__Host-` requires `Secure`.
- Mutating cookie-authenticated requests require a trusted `Origin`; cross-site Fetch Metadata requests are rejected. Bearer-token clients can make originless API calls. CORS wildcard middleware has been removed.
- Preview endpoints require authentication. All three preview iframes use `sandbox="allow-scripts"` without `allow-same-origin`; the injected bridge no longer calls privileged APIs directly. A restrictive preview CSP blocks `connect-src`, forms, nested frames, workers, and remote assets, and repeats the script-only sandbox at the response layer. The parent accepts messages only from active opaque-origin preview frames and relays bounded telemetry with its same-origin credentials. Cookie-authenticated API mutations reject untrusted/opaque Origins.
- The built app shell now receives a separate CSP: scripts only from self (no `unsafe-inline`/`unsafe-eval`), same-origin API connections and preview frames, no objects/base changes, and no embedding by other sites. It explicitly allows the Google Fonts stylesheet/font origins used by `index.html`; inline styles remain allowed for React-generated style attributes. Static assets receive `nosniff`, and the shell also sets Referrer-Policy, Permissions-Policy, and `X-Frame-Options: DENY`.
- Workspace file access rejects absolute/traversal/encoded traversal paths, sensitive path names, Git/VCS metadata (`.git`, `.hg`, `.svn`), and observed symlink components; agent reads and writes block recognized secret-like content. Git subprocesses strip inherited `GIT_*` overrides, disable system/global Git config, and force hooks off, preventing repository attributes from activating a server user's global clean filter during checkpoint commits. Observer events and textual preview assets redact recognized secret patterns.
- Worktree reads, writes, listings, Observer baseline/watcher reads, and preview asset reads now go through `@openclaw/fs-safe` root handles rather than relying only on path-string checks. The dependency is pinned to 0.28.1; the project/runtime floor is Node.js 26 LTS and native mode is required by default (`FORKSTREAM_FS_SAFE_NATIVE_MODE=auto` is an explicit weaker fallback).
- The existing lexical/path-name checks remain defense in depth. `fs-safe` documents platform- and operation-specific guarantees: its current public read results report `containment: "best-effort"`; `require` requires the native binding but does not by itself prove kernel-atomic containment. Thus this code does not claim race-free filesystem confinement.

## Explicit limitations / gates before imported projects

- `fs-safe` narrows the filesystem race surface and its read-race injection test rejects a symlink swap, but its own current public `Root.read` contract reports best-effort containment. Same-user concurrent parent-directory rename races and non-Linux operation semantics remain limitations. Do not treat the application layer or this dependency as an OS sandbox; keep imported/untrusted projects gated.
- Secret detection is pattern-based. It can miss unknown formats and has false positives; it is not a substitute for a secret manager, repository history scanning, or preventing all sensitive data from reaching a model/provider.
- This is a single-owner local-testing build: multi-user identity, roles, per-project authorization, credential-rotation UX, and audit-grade revocation are intentionally out of scope for now, not prerequisites for private localhost testing.
- No OS/container isolation, network egress policy, per-tool approval workflow, or prompt-injection containment is completed here. Do not enable autonomous agents on imported/untrusted projects until those controls and explicit user approvals are implemented and tested.
- Preview CSP intentionally blocks remote assets and application `fetch`/WebSocket; CDN-dependent previews may not render. Sandboxing prevents same-origin DOM/API access but is not a full egress sandbox: browser navigation and browser implementation differences still require caution. Do not treat previewing hostile content as safe for sensitive data.
- `SameSite` and origin checks are defense in depth; an XSS bug in the trusted parent app can still act through an authenticated browser session. Review parent-app CSP/XSS and operation-specific authorization separately.

## Evidence and design references

- [Official Node.js release schedule](https://github.com/nodejs/Release/blob/main/schedule.json): Node.js 20 reached end of life on 2026-04-30; Node.js 26 entered LTS on 2026-10-28 and is scheduled through 2029-04-30. ForkStream now requires Node 26+ so it can use a supported runtime and the pinned filesystem boundary dependency.
- [MDN CSP `sandbox` directive](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox): response-header sandboxing is broadly supported and complements the iframe attribute; only `allow-scripts` is restored for preview functionality, while same-origin, forms, popups, and top navigation remain disallowed.
- [Official AI SDK 5-to-6 migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-6-0): provider package major versions need to move with `ai`; the workspace now pins the v6 core and corresponding provider majors, then validates with typecheck and regression suites.
- [@openclaw/fs-safe v0.28.1 security model](https://fs-safe.io/security-model.html) and [pinned package metadata](https://www.npmjs.com/package/@openclaw/fs-safe/v/0.28.1): root-bounded operations vary by OS and operation; reads surface a containment class, Linux openat2 can provide kernel-atomic opens while guarded fallbacks are best-effort, and the library is not a sandbox.
- [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html): session cookies should use appropriate `HttpOnly`, `Secure`, `SameSite`, path/domain scope and expiry controls; `__Host-` is recommended for strong host scoping when HTTPS is available.
- [OWASP CSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html): recommends CSRF defenses for cookie-authenticated state changes, origin verification and defense in depth; SameSite alone is not a universal substitute.
- [OWASP LLM01: Prompt Injection](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html) and [LLM06: Excessive Agency](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM06_ExcessiveAgency.html): prompt-only defenses are insufficient; reduce capabilities, enforce permissions at execution boundaries, and use human approval for high-impact actions.
- [Docker Rootless mode](https://docs.docker.com/engine/security/rootless/) and [Docker Engine security](https://docs.docker.com/engine/security/): container isolation hardening is a separate layer and is not provided by this application-level change.

## Verification

Run `npm run typecheck`, `npm run test:web-headers`, `npm run test:preview-security`, `npm run test:security`, `npm run test:auth`, `npm run test:part01`, and `npm run test:engine` under Node.js 26+. The web-header tests exercise the shared response-header builders; an HTTP smoke check confirmed the served app shell returns its CSP and `nosniff`, the public auth status endpoint responds, and an unauthenticated preview request is denied. The filesystem security test logs the installed native binding and the actual containment class reported by a Root read; in this workspace it reported `best-effort`, and an injected post-resolution symlink swap was denied. It also confirms agent writes cannot reach `.git` metadata and that a hostile inherited global Git clean filter does not execute when agent-controlled attributes are committed. `npm audit` reported zero vulnerabilities after updating the AI SDK/provider family, Hono Node adapter, and Zod; this is a point-in-time lockfile result, not a substitute for recurring audits.
